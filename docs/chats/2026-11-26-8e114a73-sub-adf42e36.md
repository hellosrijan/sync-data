12	## 1. `apply()` (build-plan phase 2 — build this first)
13	
14	Every inbound change, from any of the three paths, goes through one function. Put it in
15	`src/sync/services.py` (new file) as `apply(change: Change) -> Result`.
16	
17	**The `Change` input** (2.1.1), a frozen dataclass or similar in the same file:
18	
19	```python
20	@dataclass(frozen=True)
21	class Change:
22	    source: str          # "salesforce" | "portal"
23	    event_id: str        # ChangeEvent.event_id — see "event_id by source" below
24	    object_type: str      # "Customer" | "Contact"
25	    record_ref: str | int  # Salesforce ID (str) for source=salesforce, portal pk (int) for source=portal
26	    occurred_at: datetime
27	    actor: str
28	    fields: dict[str, Any]   # already-decided field values (see "which fields" below)
29	    operation: str        # "create" | "update"
30	```
31	
32	**`event_id` by source** (design §8, Architecture "Where the inputs come from"):
33	
34	| Source | `event_id` |
35	|---|---|
36	| Webhook | the payload's `eventId` |
37	| Portal save | a new UUID (one per save, not per field) |
38	| Catch-up | `record_id` + Salesforce's modified time |

40	**The transaction** (2.1.2, one Postgres transaction, matches the Architecture diagram exactly):
41	
42	```python
43	def apply(change: Change) -> Result:
44	    with transaction.atomic():
45	        try:
46	            ChangeEvent.objects.create(event_id=change.event_id, source=change.source)
47	        except IntegrityError:
48	            return Result(outcome="duplicate")  # the unique constraint caught a replay
49	
50	        record = _lock_record(change)            # SELECT ... FOR UPDATE, create if new — see below
51	
52	        if change.source == "salesforce" and change.actor == INTEGRATION_USER_IDENTIFIER:
53	            return _record_echo(change, record)   # 2.2.2 — confirmation only, apply nothing
54	
55	        applied_fields = []
56	        for name, value in _changed_fields(change, record).items():      # 2.2.1
57	            stored_at = record.field_meta.get(name, {}).get("at")
58	            is_newer = stored_at is None or change.occurred_at > stored_at \
59	                or (change.occurred_at == stored_at and change.source == "salesforce")  # tie -> Salesforce
60	            FieldChange.objects.create(
61	                object_type=change.object_type, record_id=record.pk, field=name,
62	                value=str(value), actor=change.actor, source=change.source,
63	                occurred_at=change.occurred_at,
64	                status=FieldChange.Status.APPLIED if is_newer else FieldChange.Status.SUPERSEDED,
65	                event_id=change.event_id,
66	            )
67	            if is_newer:
68	                setattr(record, name, value)
69	                record.field_meta[name] = {"at": change.occurred_at.isoformat(), "source": change.source,
70	                                            "by": change.actor,
71	                                            "sf_value": value if change.source == "salesforce" else record.field_meta.get(name, {}).get("sf_value")}
72	                applied_fields.append(name)
73	
74	        if applied_fields:
75	            if record._state.adding:
76	                record.created_by = change.actor
77	            record.updated_by = change.actor                              # 2.2.4
78	        record.save()
79	
80	        if change.source == "portal" and applied_fields:                  # 2.3
81	            _upsert_outbox_row(record, applied_fields, change.operation)
82	
83	        return Result(outcome="applied" if applied_fields else "no_change", applied_fields=applied_fields)
84	```
85	
86	**`_lock_record`:** find-or-create, the one part the design leaves to implementation.
87	
88	- `source="salesforce"`: look up by `salesforce_id=record_ref`. Not found **and**
89	  `operation="create"` → create a new row with that `salesforce_id` and no `external_id`
90	  collision risk (UUID default). Use `Customer.objects.select_for_update().get_or_create(...)`
91	  inside the already-open transaction, not a separate query then a separate lock.
92	- `source="portal"`: `record_ref` is the portal pk. For a create, the row was already made by
93	  the portal view before calling `apply()` (see `drf.md`: `perform_create` calls `apply()` with
94	  the just-created instance's pk) — so this is always a lookup, never a creation, for portal.
95	- `source="catch-up"` behaves like `salesforce`.

97	**`_changed_fields`** (2.2.1 — Q2, revised 2026-11-27: the default assumption is now
98	**changed-fields-only**, matching the brief's own sample, which has exactly one field in

101	```python
102	def _changed_fields(change, record):
103	    if change.source == "portal":
104	        return change.fields          # the form only sends what changed
105	    # salesforce / catch-up: the payload normally carries only the changed fields (Q2's
106	    # default), but it may occasionally carry the whole record instead (Q2's "other way") -
107	    # this comparison is correct either way. Compare against what we last received FROM
108	    # Salesforce for that field, not against the current value - the current value may be a
109	    # newer portal edit we haven't told Salesforce about yet.
110	    return {k: v for k, v in change.fields.items()
111	            if record.field_meta.get(k, {}).get("sf_value") != v}

116	needs nothing extra — the check is a no-op (every field present already differs from
117	`sf_value` by definition). See design §7 and the brief's own city/phone scenario.

129	    row, created = Outbox.objects.get_or_create(

131	        defaults={"operation": operation, "fields": applied_fields, "next_attempt_at": timezone.now()},
132	    )
133	    if not created:
134	        row.fields = sorted(set(row.fields) | set(applied_fields))

149	## 2. Outbound task (build-plan phase 5)
150	
151	New file `src/sync/tasks.py` (Dramatiq actors; this is what `<app>/tasks.py` discovery in
152	`CLAUDE.md` is for).
153	
154	```python
155	@dramatiq.actor(max_retries=0)          # the outbox drives retries, not Dramatiq (design §6, Q7)
156	def send_outbound():
157	    now = timezone.now()
158	    for row in Outbox.objects.select_for_update(skip_locked=True).filter(
159	            state=Outbox.State.PENDING, next_attempt_at__lte=now
160	    ).order_by("next_attempt_at"):
161	        with transaction.atomic():
162	            row.lease_until = now + timedelta(seconds=60)
163	            row.save(update_fields=["lease_until"])
164	        _send_one(row)   # reads CURRENT field values at send time, not a stored snapshot (Architecture)
165	```
166	
167	- **`SKIP LOCKED`** is why two worker processes never fight over the same row — the loop body
168	  must run inside its own short transaction per row, not one transaction for the whole batch,
169	  or `SKIP LOCKED` can't do its job.
170	- **Current values, not a snapshot:** read `getattr(record, field)` for each name in
171	  `row.fields` right before sending — this is what makes several merged edits collapse into one
172	  call and makes a retried send harmless (Architecture, "We send the current value").
173	- **Outcome handling** (5.3.2), one `match`/`if` block in `_send_one`:
174	
175	  | Outcome | Action |
176	  |---|---|
177	  | accepted | `row.state = SENT`; `row.sent_at = now`; on a create, `record.salesforce_id = <returned id>; record.save()` |
178	  | unreachable / timeout / 5xx | `row.attempts += 1; row.next_attempt_at = now + min(2**row.attempts, 60)s; row.lease_until = None` |
179	  | 429 | same as above but also call the limiter's slow-down (below); honour `Retry-After` if present |
180	  | 400-type (bad data) | `row.state = NEEDS_REVIEW; row.last_error = <message>` — never deleted (Q9) |
181	  | 401/403 | stop the whole task early and raise/alert — don't keep burning the rate limit on calls that will all fail |
182	
183	- **Wake-up:** `transaction.on_commit(lambda: send_outbound.send())` wherever `apply()` (or the
184	  portal view) commits a change that touched the outbox, **plus** a crontab job
185	  (`dramatiq_crontab`, `@interval(seconds=5)`) that calls `send_outbound.send()` unconditionally
186	  as a backstop for a lost wake-up (5.3.3). The task itself is idempotent (it only sends rows
187	  that are actually due), so calling it extra times is harmless.

189	## 3. Shared rate limiter (5.2)
190	
191	One Redis key, one Lua script (atomic token bucket), used by **every** caller: sends, retries,
192	the probe, and catch-up queries. Put it in `src/sync/limiter.py`.
193	
194	- State in Redis: current allowed rate (starts at `settings.SALESFORCE_RATE_LIMIT`) and a token
195	  count, refilled continuously.
196	- `limiter.acquire(timeout=...)` blocks (or the caller re-queues) until a token is free.
197	- On a 429: `limiter.throttle()` halves the current rate immediately, then a crontab job
198	  (`@interval(seconds=30)`) adds 5 req/s back, capped at the configured limit, until it's
199	  recovered.
200	- Test with `redis-py`'s real client against the Redis the compose stack already runs — no
201	  need to mock Redis for this.

203	## 4. Down detection and probe (5.4)
204	
205	`SyncState` row `key="salesforce"`, `value={"status": "up"|"down", "consecutive_failures": N}`.

207	- Every outbound failure classified as "unreachable" increments `consecutive_failures`; any
208	  success resets it to 0.
209	- At 5, set `status="down"`. While down, `send_outbound` should skip sending (checked at the
210	  top of the task) so it doesn't burn attempts against a Salesforce that's confirmed down.

212	  `status="up"`, `consecutive_failures=0`, then **run catch-up before anything else** (next
213	  section), then let `send_outbound` resume on its own next tick.

215	## 5. Catch-up (build-plan phase 6)

219	1. Read `SyncState.key="watermark"` (a timestamp); subtract a few minutes of overlap.
